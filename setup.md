# Development Setup Guide

This guide explains how to clone the repository, install its dependencies, validate the source, and run the local development environment.

## 1. Prerequisites

Install the following software before cloning the repository:

- [Git](https://git-scm.com/downloads)
- [Node.js](https://nodejs.org/) `22.12.0` or newer within the Node 22 LTS release
- npm, which is included with Node.js
- A code editor such as [Visual Studio Code](https://code.visualstudio.com/)
- A browser wallet such as MetaMask, required only for browser-to-blockchain transactions

Check the installed versions:

```bash
git --version
node --version
npm --version
```

The expected Node.js version is:

```text
v22.12.0 or newer, but lower than v23
```

Using a different Node.js major version may cause Hardhat or Vite compatibility errors.

## 2. Clone the repository

Copy the HTTPS or SSH clone URL from the repository hosting page, then run:

```bash
git clone <repository-url>
cd <repository-folder>
```

Example:

```bash
git clone https://github.com/<account>/<repository>.git
cd <repository>
```

Do not include the angle brackets when replacing the example values.

## 3. Install dependencies

The repository contains two Node.js packages:

- the root package for smart contracts, tests, and deployment;
- the `frontend` package for the browser interface.

Install the exact versions recorded in both lockfiles:

```bash
npm ci
npm --prefix frontend ci
```

Use `npm ci` after cloning because it provides a reproducible installation from `package-lock.json`. Use `npm install` only when intentionally adding or updating a dependency.

The generated `node_modules` directories are local dependencies and must not be committed.

## 4. Validate the installation

Run the complete validation command:

```bash
npm run check
```

This command:

1. compiles the Solidity contracts;
2. runs the Hardhat test suite; and
3. creates a production frontend build.

The setup is ready when all three stages complete successfully.

Individual checks can also be run separately:

```bash
npm run compile
npm run test
npm run frontend:build
```

## 5. Create local environment files

Environment files are excluded from Git because they may eventually contain local configuration or secrets.

### Windows PowerShell

```powershell
Copy-Item frontend/.env.example frontend/.env
```

### macOS or Linux

```bash
cp frontend/.env.example frontend/.env
```

The default frontend configuration is:

```dotenv
VITE_CHAIN_ID=31337
VITE_RPC_URL=http://127.0.0.1:8545
VITE_MODEL_REGISTRY_ADDRESS=
```

Leave the contract address empty until the local deployment is complete.

The root `.env.example` is only for an optional public-testnet deployment. It is not required for local development.

## 6. Start the local blockchain

Open a terminal in the repository root and run:

```bash
npm run node
```

Keep this terminal open. The local blockchain normally uses:

```text
RPC URL: http://127.0.0.1:8545
Chain ID: 31337
```

Hardhat displays temporary development accounts and private keys when the node starts. These keys are publicly known testing credentials.

> Never send real cryptocurrency to a Hardhat development account. Never reuse a displayed development key on a public network.

Stopping the local node discards its in-memory blockchain state unless a separate persistence method has been configured.

## 7. Deploy the contract locally

Keep the local blockchain running. Open a second terminal in the repository root and run:

```bash
npm run deploy:local
```

The deployment output includes the contract address. Copy that address into `frontend/.env`:

```dotenv
VITE_MODEL_REGISTRY_ADDRESS=0xREPLACE_WITH_DEPLOYED_ADDRESS
```

Use only the address generated by the current local deployment. Restarting the blockchain and deploying again may produce a new deployment state.

## 8. Configure a browser wallet

Add a custom local network to the wallet:

```text
Network name: Hardhat Local
RPC URL: http://127.0.0.1:8545
Chain ID: 31337
Currency symbol: ETH
```

For local testing only, import one of the temporary accounts printed by `npm run node`.

Use different development accounts when testing authorization:

- account 1 can act as the initial administrator or publisher;
- another account can act as an ordinary verifier; and
- an additional account can test rejected unauthorized operations.

## 9. Start the frontend

Open a third terminal in the repository root and run:

```bash
npm run frontend:dev
```

Vite prints the local application URL, normally:

```text
http://localhost:5173
```

Open that URL in the browser containing the configured wallet.

The usual development session therefore uses three terminals:

| Terminal | Command | Purpose |
|---|---|---|
| 1 | `npm run node` | Local blockchain |
| 2 | `npm run deploy:local` | Contract deployment; can exit after success |
| 3 | `npm run frontend:dev` | Frontend development server |

## 10. Available commands

Run these commands from the repository root unless stated otherwise.

| Command | Description |
|---|---|
| `npm run compile` | Compile Solidity contracts |
| `npm run test` | Run contract tests |
| `npm run node` | Start the local Hardhat blockchain |
| `npm run deploy:local` | Deploy to the running local blockchain |
| `npm run frontend:dev` | Start the frontend development server |
| `npm run frontend:build` | Create a production frontend build |
| `npm run check` | Compile, test, and build everything |

## 11. Normal development workflow

Before starting a change:

```bash
git switch main
git pull
git switch -c <branch-name>
```

Use a short branch name that describes the change, for example:

```bash
git switch -c feature/register-model
git switch -c test/revocation-rules
git switch -c fix/wallet-network-warning
```

During development:

```bash
npm run compile
npm run test
npm run frontend:build
```

Before committing:

```bash
npm run check
git status
```

Commit only source code, tests, documentation, and intentional configuration changes. Do not commit generated dependencies, secrets, local deployment output, or large model binaries.

## 12. Updating dependencies

Do not delete or regenerate lockfiles during normal setup.

When a dependency change is intentional:

```bash
npm install <package-name>
```

For a frontend dependency:

```bash
npm --prefix frontend install <package-name>
```

Commit the corresponding `package.json` and `package-lock.json` changes together. Run `npm run check` after every dependency update.

## 13. Troubleshooting

### Unsupported Node.js version

Check:

```bash
node --version
```

Install a compatible Node 22 LTS release, remove dependencies installed with the incompatible runtime, and run both `npm ci` commands again.

### `npm ci` reports that the lockfile is out of date

Do not bypass the error with flags. Pull the latest repository changes first. If dependency changes were intentional, the contributor who changed `package.json` should regenerate and commit the matching lockfile using `npm install`.

### Port `8545` is already in use

Another local blockchain may already be running. Stop the old process or configure the node, wallet, Hardhat network, and frontend to use the same alternative port.

### Port `5173` is already in use

Vite may automatically select another port. Open the exact URL printed in the terminal.

### Wallet shows the wrong network

Switch to the local network with chain ID `31337`. Confirm that the RPC URL matches the running Hardhat node.

### Contract calls fail after restarting the node

Redeploy the contract and update `VITE_MODEL_REGISTRY_ADDRESS` with the new local address. Restart the frontend after editing its `.env` file.

### Contract artifact or address is missing

Compile and deploy again:

```bash
npm run compile
npm run deploy:local
```

Confirm that the local blockchain is still running in another terminal.

### Frontend changes are not visible

Check the terminal for compilation errors. If `.env` changed, stop and restart `npm run frontend:dev` because environment variables are loaded when Vite starts.

## 14. Security rules

- Never commit `.env` files.
- Never commit a private key, seed phrase, API token, or funded wallet.
- Never use Hardhat's printed development keys on a public network.
- Never store large files or confidential metadata directly on-chain.
- Verify an external file's source and licence before adding it to a demonstration.
- Review dependency changes before committing updated lockfiles.
- Use a dedicated, disposable wallet for any optional public-testnet deployment.

## 15. Clean-clone verification

Before creating a release or merging a major setup change, verify the repository from a fresh clone:

```bash
git clone <repository-url> clean-check
cd clean-check
npm ci
npm --prefix frontend ci
npm run check
```

A successful clean-clone check confirms that no uncommitted local file is required to build or test the repository.
